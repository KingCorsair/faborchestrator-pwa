# Next.js 16.1.4 → 16.3.6: revalidating the plan's Next.js evidence

30 September 2026. Before adopting the chetan branch's upgrade (`679c560`), every
claim in `docs/architectural_review_issues/PWA_ARCHITECTURAL_REMEDIATION_PLAN.md`
(revision 3.13) that was read in or measured on Next 16.1.4 was rerun on both
versions.

**Method.** One throwaway Next app (root `proxy.js` with the `/(.*)` matcher, a
`next.config.mjs` `headers()` rule, route handlers, a throwing page and a
`public/sw.js`), installed twice (Next 16.1.4 and 16.3.6, React 19.2.3, Node
24.19.0), built with `next build` and served with `next start`. The same probe
script (raw `node:http`, so it could forge `Host`, pause an upload and
disconnect mid-response) ran against each. The ceiling probe ran a second time
with `experimental.proxyClientMaxBodySize` set only at server start. Claims
that came from reading Next's source were compared file against file in the
two installs.

## Runtime probes: identical on both versions

| Probe | Plan claim | 16.1.4 | 16.3.6 |
|---|---|---|---|
| N1 | Next receives the whole upload before a `proxy.ts` refusal is sent (WHOLE-R1) | 413 sent only after the full 12 MB arrived | same |
| N2 | `proxyClientMaxBodySize` default 10 MB truncates silently; the value is read at `next start` | declared 12 MB → route saw 10,485,625 bytes, chunked → 10,485,760, "Request body exceeded 10MB" logged; with 25 MiB set at start only → 12,582,912 both ways; the rewrite's request-header marker arrived | same |
| N3 | Single-valued header precedence: middleware > config `headers()` > route (G33) | `x-probe: middleware`; `cache-control` from config over the route's | same |
| N4 | Next's error renderer writes its own `cache-control` on error documents | 500, `private, no-cache, no-store, max-age=0, must-revalidate` | same |
| N5 | A same-host 307 from `proxy.ts` is emitted origin-relative, whatever `Host` says | `Location: /login` with `Host: evil.example` and without | same |
| N8 | `req.signal` aborts on an early client close, not after a normal finish | full read: no abort; early disconnect: abort | same |
| N9 | Next cancels an upstream body being piped when the client disconnects | cancelled | same |
| N10 | `after()` runs under `next start` | ran once | same |
| N11 | `maxDuration` is not enforced at runtime | `maxDuration = 1` route finished after 3 s with 200 | same |
| N13 | `public/` files are served through the `/(.*)` proxy matcher | `/sw.js` 200, `application/javascript` | same |

The two result files were byte-identical (`diff` empty).

## Result

No claim in revision 3.13 changes its truth value on 16.3.6. Only line numbers
in the `[Next-src]` citations move (listed above). N14 (the app's own suites,
`next build`, and its own runtime probes on 16.3.6) had not run when this was
written: the machine's Node.js installation lost `node.exe` partway through
the upgrade of this app's dependencies.
